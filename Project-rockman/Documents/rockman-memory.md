## 2026-08-10 — 项目启动：Rockman X4 操作原型

### 项目初始化

- 从零开始构建 Rockman X4 风格操作原型
- 单文件 HTML Canvas 实现
- 分支：`dev/rockman`

### 操作键位设计 [当前方案]

经过多轮迭代确定最终键位：
- **J**：射击 + 蓄力（合并，短按射击、长按蓄力）
- **K**：跳跃 + 墙跳
- **L**：Dash（冲刺）
- **A/D**：左右移动
- W 键已取消，Shift 键已取消

### 蓄力机制演变 [当前方案]

最终方案：三区间蓄力
- 按下 J 瞬间发射普通子弹
- 0~0.1s（6 帧）：松手不发射蓄力弹
- 0.1~1s（6~60 帧）：松手发射小型蓄力炮
- 1s+（60 帧）：蓄力满，松手发射大型蓄力炮
- 满蓄力时间从最初 2s → 改为 1s

### Dash 机制演变 [当前方案]

经过多轮重大重构：

**v1**：固定时长冲刺 + 冷却时间（原始原型）
**v2**：两阶段机制（冲刺阶段 + Dash 就绪状态），无冷却
**v3**：去掉 `dashJumpBonus` 中间状态，改用 `lRaw` 直接判断
**v4** [当前方案]：引入 `dashAirborne` 标记

当前最终方案：
- Dash 仅地面可用，无冷却时间
- **阶段 1**：冲刺阶段（1.5 倍速，最大 128px/4Tile）
- **阶段 2**：就绪状态（冲刺结束后 L 还按着，普通移速，起跳获得 Dash 资格）
- **空中 Dash 资格**（`dashAirborne`）：一旦触发（通过冲刺中起跳/就绪中起跳/按住L地面起跳/按住L墙跳），松 L 也保持，直到落地或贴墙才清除
- 空中 Dash 资格期间：按方向键 1.5 倍速，不按静止
- 落地即刷新 Dash 权限，但 L 键需松手再按才能触发新 Dash
- 残影系统：冲刺阶段 + 空中 Dash 资格期间每 3 帧记录残影，12 帧渐隐

**关键决策**：
- 冲刺阶段结束后不自动移动（去掉了阶段 2 的自动移动逻辑）
- 空中加速不依赖 L 是否按住（`dashAirborne` 独立于 `lRaw`）
- L 键消费机制与冲刺中止判断分离（冲刺内用 `lRaw` 判断松手）

### 墙跳锁定 [当前方案]

- 墙跳后 0.1s（6 帧）强制向反方向移动
- 方向由蹬墙瞬间保存的 `wjDir` 字段决定（不再依赖逐帧重算的 `onWall`）
- 锁定期间忽略玩家方向键输入
- Dash 加速块在锁定期间不干预（让普通移动块强制控制）
- 锁定结束后 Dash 加速才接管

### 贴墙机制 [当前方案]

- 贴墙滑落需要按住面向墙的方向键
- 松手自由下落
- 贴墙时射击方向为反方向（远离墙）
- 贴墙时清除空中 Dash 资格（改为"刚贴墙时"清除，避免墙跳时被覆盖）

### 跳跃消费机制 [当前方案]

- K 键按住只触发一次跳跃（消费机制）
- 松手重置消费标记
- 防止按住 K 连跳

### 角色外观

- 高度改为原始 2 倍（40px → 80px）
- 像素风格 X（艾克斯）造型：蓝色身体、红色头盔角、炮臂

### 残影效果

- 初始：单个半透明残影
- 改进：多个渐隐残影（每 3 帧记录，12 帧生命周期，约 7 个残影形成拖尾）
- 残影录制范围扩展到空中 Dash 资格期间

### 子弹速度

- 初始：7.0 → 翻倍为 14.0

## 2026-08-11 — 关卡编辑系统 + 文档同步合并 main (下午)

### 关卡数据抽离 [当前方案]

- 新建 `level.json`：用规则格式描述 tiles（`{col, row, value}` 支持单值和区间）+ enemies 列表

- 删除了原来的 `buildMap()` 函数和硬编码 `spawns` 数组

### 可视化编辑器 [当前方案]

- 按 `E` 切换编辑/游玩模式
- 编辑模式下游戏逻辑完全暂停（`update()` 直接 return），怪物静止在初始位置，玩家不渲染
- 两种工具：砖块（左键放置/右键删除）和敌人（下拉选择类型后放置）
- **长按机制**：按住左键/右键并拖动鼠标，持续放置/删除，不用反复点击
- 敌人放置去重：同一位置 8px 内已有敌人时不重复放置
- 鼠标悬停高亮当前 tile / 显示敌人预览框
- 编辑器工具栏右上角固定，含工具切换按钮 + 敌人类型下拉 + 操作提示

### 中键拖拽平移 [当前方案]

- 编辑模式下按住鼠标中键（滚轮按下）拖动，自由平移摄像机（水平+垂直）
- 拖拽速度适配缩放因子（`/ camera.zoom`），缩小拖得快、放大拖得精准
- 退出编辑模式时自动重置 camera.y 和 zoom

### 滚轮缩放 [当前方案]

- 编辑模式下滚轮以鼠标位置为中心缩放，范围 0.2x ~ 4.0x，步进 0.1
- 统一世界变换：`ctx.translate(-cx*zoom, -cy*zoom)` + `ctx.scale(zoom, zoom)`，所有渲染函数直接用世界坐标
- 缩放后鼠标坐标计算正确适配：`screenX / zoom + camera.x`

### 动态地图扩展 [当前方案]

- 编辑模式下在边界外放置砖块时自动扩展 map 数组
- `LW`/`LH`/`MAP_W` 从 const 改为 let，`map` 直接整体替换（不用逐索引复制）
- 扩展时同步偏移所有敌人坐标（x, y, baseY, pMin, pMax）和摄像机，保持画面不跳动

### 摄像机居中跟随 [当前方案]

- 游玩模式摄像机水平+垂直居中跟随玩家，平滑插值 0.12
- 边界限制：走到地图边缘时镜头停止，玩家可以出现在画面边缘
- 退出编辑模式时重置摄像机定位到玩家居中位置

### JSON 导出 [当前方案]

- `Ctrl+S` 弹出导出面板
- `exportLevelJSON()` 将当前 map 压缩为规则格式（合并连续行列）+ 敌人列表 + playerSpawn
- 支持一键复制到剪贴板或下载为 JSON 文件

## 2026-08-12 (下午) — 序列帧处理流程讨论

### 素材现状

- 角色动画素材（idle.png, running.png, jump.png, shoot.png 等）从「爱给网」下载，无配套 JSON 元数据
- 部分素材帧宽可能不统一，导致自动检测不准
- 当前 `prototype.html` 中角色仍使用 `fillRect` 占位美术，尚未接入序列帧素材

### Spritesheet 标准工作流（知识记录）

游戏开发中处理序列帧的正规流程：

1. 美术在 Aseprite 中画好动画（每帧独立在时间轴上）
2. File → Export Sprite Sheet，勾选「Export JSON data」
3. 导出两个文件：`xxx.png`（序列帧图）+ `xxx.json`（每帧坐标/尺寸元数据）
4. 游戏代码加载 JSON → 按坐标从 PNG 切出每帧渲染

此流程完全不需要"检测帧宽"，JSON 已精确描述每帧位置。

### 当前情况：无配套 JSON

素材来源是现成下载的 PNG，没有 JSON。处理方案：

- **路 A**：工具辅助逐帧手动标记，支持不等宽帧，导出 `[{ x, w }]` 格式
- **路 B**（推荐）：用 Aseprite 重新导入 → 手动切片 → 导出统一帧宽的干净 Spritesheet

### preview.html 改进方向（待实施）

当前问题：整图切分模式只展示自动检测边界线，手动参数无法在整图上可视化验证。

改进方案：**双轨对比展示**
- 紫色半透明 = 自动检测的帧边界（仅供参考）
- 橙色实线 = 当前手动参数的帧边界（随滑块实时变化）
- 拖动帧宽滑块时橙色线实时跟随，人工验证切分是否对齐

## 2026-08-13 — 序列帧切割工具链 + 小蓄力子弹 sprite 接入

### 序列帧切割工具链

由于素材（从「爱给网」下载）无配套 JSON，开发了两条切割路径：

**工具 A：`sprite-cutter.html`（网页交互式）**
- 流程：加载图片 → 调绿幕容差 → 框选动画行 + 分割线 → 导出等宽条带 PNG / 每帧坐标 JSON
- 必须在本地浏览器打开（双击用 Chrome/Edge），不要在 CodeBuddy 预览里操作（webview 会拦截下载）

**工具 B：`sprite-build.js`（本地脚本，零依赖）**
- 内置 PNG 编解码（仅支持 8bit RGBA/RGB 非隔行）
- 读取参数 JSON（`sprite-params.json`），产出 `{prefix}_clean.png` / `{prefix}_strip.png` / `{prefix}_frames.json`
- 与网页算法一致，适合批量/脚本化生成

### 去绿幕算法演变 [当前方案]

这是本次会话攻克的核心难题，经历了三次迭代：

**v1（旧算法，有 bug）**：宽泛阈值判断 `g > r + tol && g > b + tol && g > 80`，把"偏绿的像素"都删掉。

**问题暴露**：`middle-bullet.png` 的子弹本体是白色 + **绿色描边**（`0,168,88`、`0,200,104`、`0,224,104`、`104,248,176`），背景是纯绿 `(0,255,0)`。旧算法把子弹的绿色描边也当背景删了，导致导出"像素变大、中间空白、只剩零星点"。

**v2（泛洪填充，未采用）**：从图片边缘纯绿背景 flood fill，只删连通的绿色。验证后发现问题依旧——子弹描边与背景连通，泛洪填充照样误删。

**v3（当前方案，精确删纯绿）**：只删除「贴近纯绿」的像素，判定条件改为 `g >= 255 - tol && r <= tol && b <= tol`。关键在 `r <= tol && b <= tol`：前景绿色描边如 `0,168,88` 蓝分量 88 > tol(30)，不会误删；只有纯绿背景 `0,255,0`（红 0 蓝 0）命中。验证：middle-bullet 各帧内容像素数从 117/79/48/178/176 提升到 205/190/224/348/376，纯绿残留 0。

**关键教训**：去绿幕不能假设"前景不含绿色"。当素材本身含绿色描边时，必须用精确匹配背景色（而非宽泛的"偏绿"阈值）来区分背景和前景。

### resetView 默认选区修复

原 `resetView()` 加载图片后默认选区 = 整图（`y0=0, y1=612`），导致 `getContentBBox` 扫描整个高度，每帧混入多行内容。改为：自动检测水平行后选第一行。导出时增加多行警告（选区高度 > 图高 35% 时弹窗确认）。

### 小蓄力子弹 sprite 接入

`prototype.html` 中 power=1（小蓄力子弹）原用纯色矩形绘制，现改为 sprite 动画：
- 资源：`middle-bullet-flying_strip (1).png`（等宽条带 5 帧 × 40×19）
- 显示尺寸 54×36（匹配碰撞体积，用户确认放大到匹配尺寸）
- 5 帧循环播放，fps=10；`dir < 0` 时水平镜像
- 碰撞体积不变（54×36），只改视觉，不影响游戏平衡
- 图片未加载完成时回退纯色矩形

**待确认/遗留**：文件名带空格和括号 `(1)`（浏览器重复下载自动加），虽能加载但建议后续重命名为规范名（需用户同意）。

### 清理

删除临时调试脚本（debug-*.js）、错误整图选区生成的 test-idle 废产物、临时 sprite-params.json。

## 2026-08-13 (会话#6) — 角色序列帧动画系统接入 + 动画细节打磨

### 角色精灵动画系统 [当前方案]

- 角色从 `fillRect` 占位美术正式替换为 9 个序列帧精灵动画
- 动画 key 与资源前缀映射：`stand/shoot/running/jump/dash/climb/runShoot/jumpShoot/dashShoot` → `idle-*` 前缀
- `loadPlayerSprites()` 启动时 fetch 各动画 `_frames.json` + `_strip.png`
- 绘制：以 `PLAYER_TARGET_H(80px)` 等比缩放，脚底对齐碰撞盒底部、水平中心对齐；未加载回退手绘小人 `drawX()`
- 帧数实测：stand=4、shoot=2、running=10、jump=7、dash=2、climb=3、runShoot=10、jumpShoot=7、dashShoot=2

### climb 镜像基准修正

- 关键发现：`climb` 资源三帧默认**面向左**（抓着墙看脸的方向），与其他动画默认**面向右**相反
- 修复：`drawPlayerSprite` 中 `flip = (animKey === 'climb') ? (facing > 0) : (facing < 0)`，climb 单独反向
- 用户强调「没这么复杂，直接左右镜像就对了」，即只需反向 climb 的翻转基准，无需改动 facing 数值逻辑

### 同帧数动画对逐帧对应

- jump↔jumpShoot（各 7 帧）、running↔runShoot（各 10 帧）切换时保留 `animF` 帧索引，不再重置为 0
- 效果：跳跃播到第 3 帧按下射击 → jumpShoot 从第 4 帧继续，节奏不被打断
- 实现：`KEEP_FRAME_PAIRS` 常量判断成对动画，命中则 `keepFrame=true` 跳过 `animF=0`

### 射击动画缓冲

- 需求：松开射击键后，射击动画保留一段时间再切回非射击动画
- 实现：新增 `shootHold` 字段，`isChg` 由 true→false 时设为帧数；`playerAnimKey` 中 `shooting = isChg || shootHold > 0`
- 缓冲时长经用户调整：0.5s → 0.25s（15 帧）

### 跳跃三段式播放

- 需求：跳跃动画分三段——起跳播前 4 帧 → 空中定格第 4 帧 → 落地播尾段（567 帧）后切站立
- 实现：新增 `landing` 字段，落地检测时（`grounded` false→true 且当前是 jump/jumpShoot）置 true
- `playerAnimKey` 中 `airborne = !grounded || landing`，落地收尾期间仍返回 jump/jumpShoot
- 帧推进：空中 `animF>=3` 定格；落地 `landing=true` 后从索引 3 继续播到 nf，播完清 `landing`、`animF=0` 切回站立

### 动画播放速度加速

- 需求：动画播放速度加速 1.5 倍
- 实现：`frameDur = Math.round(60 / fps / 1.5)`，所有动画统一生效

## 2026-08-14 (会话#7) — 下蹲系统 + 碰撞盒重构 + 蹬墙方向修复

### 下蹲系统 [当前方案]

- 新增 `S` 键下蹲（按住下蹲、松开站起），仅地面且非冲刺/空中 Dash 期间处理

### 碰撞盒重构 [当前方案]

- 碰撞盒从固定 `P.PW/P.PH`(28×80) 重构为动态双碰撞盒系统
- 引入 `SPRITE_SCALE = PLAYER_TARGET_H / 35 ≈ 2.286`（以站立素材高 35px 对齐 80px 为锚）
- `HITBOX` 四种状态：`stand`/`jump`（碰撞盒 A=69×80，站立素材 maxW/maxH）、`dash`/`crouch`（碰撞盒 B=87×62，宽=dash 素材、高=crouch 素材）
- `updateHitboxTable()` 在素材加载完成后依据各动画实际 `maxW`/`maxH` 计算，并回写 `P.PW/P.PH/P.PC`
- `setPlayerBox(w, h)` 切换时保持脚底 `y+h` 与水平中心 `cx` 不变

### 蹬墙方向强制位移 bug 修复 [当前方案]

这是本次会话攻克的核心问题，经历完整推理链：

**问题现象**：蹬墙后的 0.1s 强制位移"感觉只对冲刺蹬墙生效，普通蹬墙没生效"。

**根因定位**：
- 移动逻辑 `if (p.wjLock > 0) { p.vx = -p.onWall * P.WALL_JUMP_X; }` 每帧读取 `p.onWall`
- 但 `onWall` 在角色离墙瞬间（下一帧）即被 `wallCheck` 重算为 0
- 于是普通蹬墙的强制位移变成 `-0 * 5.5 = 0`，方向锁定立即失效

**为什么冲刺蹬墙"看起来对"（巧合而非正确）**：
- 冲刺蹬墙设置 `dashAir = true`，导致移动逻辑外层 `if (!p.isDash && !p.dashAir)` 为假，`wjLock` 分支根本不执行
- 而 `dashAir` 加速分支又有 `p.wjLock <= 0` 条件，`wjLock` 期间也不执行
- 所以冲刺蹬墙的 `vx`（蹬墙瞬间写死的 `-onWall * WALL_JUMP_X * DASH_MULT`）在 0.1s 内无人覆盖，靠"碰巧没被改"维持，方向稳定只是偶然

**修复方案**：新增 `wjDir` 字段，在蹬墙触发时保存 `p.wjDir = -p.onWall`，移动逻辑改为读 `p.wjDir` 而非 `onWall`。两条蹬墙路径（普通/冲刺）统一显式保持方向，不再依赖脆弱状态。
