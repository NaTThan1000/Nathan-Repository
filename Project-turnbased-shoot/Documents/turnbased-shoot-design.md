## 1. 游戏定位

### 1.1 一句话概念

**【已记录】受《以撒的结合》启发的回合制 Roguelike 地牢射击游戏：玩家探索房间，在自己的回合内即时移动和射击，并可回溯本回合操作；结束回合后，怪物集中行动。玩家通过回合决策和随机道具应对危险、推进地牢。**

### 1.2 目标玩家

- **【已记录】希望照顾操作能力较低、也想体验《以撒》式危险与随机道具乐趣的玩家。**
- **【已记录】规则学习门槛偏低：玩家无需预先学习大量规则即可开始，重要信息应直观；策略深度偏轻至中，普通情况可快速判断，危险局面允许深入思考。**
- **【目标／待实现】中等失败代价：接受单局失败后重开，计划加入一定程度的局外养成；具体保留内容和代价待讨论，时长目标见第 3 节。**
- **【已记录】初衷是致敬《以撒的结合》；后续以本项目 demo 的实际需要和范围为准，不刻意复刻，体验存在差异可以接受。**

### 1.3 核心体验与设计支柱

1. **【已记录】低操作门槛：通过回合制行动与回合内即时操作降低操作要求，期望玩家快速看懂局面并行动；节奏与难度待试玩验证。**
2. **【已记录】危险应对的刺激：让玩家依据清晰危险信息做选择；单怪完整威胁预告已接入，正式版完整试玩待反馈。**
3. **【已记录】随机道具惊喜：期待组合改变攻击方式与游玩体验，产生惊喜和爽感；当前内容能否支撑有待验证。**

**【已记录／待验证】战斗体验偏向轻松爽玩：普通战斗以直觉和爽感为主，Boss 或少数危险房间需要更多思考；具体比例和节奏通过试玩验证。**

### 1.4 差异化与边界

- **【已记录／待验证】首要差异化：回合内即时移动和射击，追求即时制所见即所得的快节奏快感；回溯提供试错安全感，让玩家尝试寻找更优解。具体体验待试玩验证。**
- **【已记录】策略与规则保持低学习门槛、轻至中等深度，尽量保持并可依开发需要调整；大多数情况无需认真推演即可找到最优解，允许损失部分血量仍通关。情绪偏紧张但轻松、荒诞快乐，避免过于阴暗压迫；具体叙事待设计。**

## 2. 玩家实际怎么玩

### 2.1 玩法概述

**【原型现状】玩家探索地牢房间，遭遇敌人后用 MP 移动、AP 射击，可在玩家回合内回溯；结束回合后怪物行动。玩家获取道具与资源，探索商店和宝箱，击败楼层 Boss 并继续推进，生命耗尽则重开。**

### 2.2 循环结构

| 层级 | 玩家行为与目的 | 状态 |
|---|---|---|
| 一次决策 / 战斗 | **观察局面 → 移动、射击并可回溯 → 结束回合 → 怪物行动 → 重复至清房或失败。** | **【原型现状】** |
| 单局 | **探索房间 → 战斗 → 获取道具与资源 → Boss → 下一层 → 通关或失败。** | **【原型现状】** |
| 跨局 | **计划加入一定程度的局外养成；具体内容和重复游玩的长期结构尚未确定。GDD 已同步新方向；旧“无局外成长”仅为历史实现描述。** | **【目标／待实现／待讨论】** |

### 2.3 关键决策与挑战

- **【原型现状】选择移动位置、射击方向和顺序、是否回溯、何时结束回合，以及使用炸弹和资源。**
- **【设计倾向／待验证】鼓励玩家寻找相对安全的位置同时积极进攻、尽快减少敌人；地图空间有限，持续躲避可能被包围而难以避免伤害。需试玩验证压力和提示是否清楚，避免过度谨慎成为最佳策略。**
- **【待讨论】探索、道具获取及经济应提供什么独立且有意义的决策。**

**【目标／待验证】难度中等偏简单：普通水平玩家初次游玩一次通关的概率极小，通过反复尝试、适应内容及解锁局外提升，几乎都能通关；顶尖玩家无需局外成长也有较大概率首次通关。具体概率、局外养成和难度曲线未定，需通过试玩验证。前期失败可能来自遗漏或忽略地图信息；当玩家对怪物攻击模式有一定了解，并能基本把握地图显示的信息后，应基本能找到战斗中的最优解。信息是否清晰可见、失败原因是否可理解需试玩验证。**

## 4. 核心系统概览

| 系统 | 玩家做什么 | 设计目的 | 与其他系统的关系 | 状态 |
|---|---|---|---|---|
| 战斗 | **移动、射击、结束回合及回溯。** | **降低操作门槛并应对危险。** | **敌人、地形、道具影响局面；MP 与 AP 独立。** | **【原型现状】** |
| 探索 / 关卡 | **在房间和楼层间移动，寻找奖励与 Boss。** | **推进地牢并发现内容。** | **房间连接战斗、资源和成长。探索深度待设计。** | **【原型现状／待讨论】** |
| 成长 / 构筑 | **拾取随机道具，改变属性及部分攻击效果。** | **目标是形成不同组合与惊喜。** | **影响战斗能力和方式；组合深度需验证。** | **【原型现状／待验证】** |
| 资源 / 奖励 | **收集生命、金币、钥匙、炸弹等，在商店消费或使用。** | **支持生存和推进。** | **关联探索、恢复、购买和战斗；经济取舍待设计。** | **【原型现状／待讨论】** |
| 危险提示 | **行动时观察单怪完整危险范围和来源感叹号。** | **帮助快速理解风险并决策。** | **随局面更新；固定随机结果，预告与实际复用，射击优先选来源。** | **【已实现／待完整试玩】** |

## 5. 玩家体验与呈现

- **【待讨论】新手教学顺序，尤其是 MP、AP、结束回合与回溯的引导。**
- **【已实现／待完整试玩】红格展示动态选择的单只威胁怪物的完整潜在范围，感叹号关联来源，无敌也预告。固定本回合随机种子，怪物回合保留结束前范围；详见 context §2.1 和 memory 2026-11-02。**
- **【原型现状】Scrap Star 美术已审核并接入核心试玩与正式版，仅替换有对应资源的内容；主角、两种机器人、房间模块、箱子、UI 与子弹特效已接入，其他内容保持原样。声音与叙事细节待设计。**
- **【待验证】危险信息与实际结果一致，玩家能理解受伤原因；辅助功能及可用性目标待讨论。**

## 6. 项目范围与原型验证

### 6.1 项目约束

**【已记录】继续使用 HTML 制作展示 demo，先评估美术效果再决定是否试验 Godot，不刻意复刻以撒内容体量。团队、工期及预算待确认。**

### 6.2 最小可玩版本

- **【已记录】验证低操作门槛、危险应对及随机成长体验。**
- **【待讨论】完成验证所需的最小敌人、房间、道具和完整流程；哪些内容推迟。**
- **【已实现／待完整试玩】每玩家回合最多回溯 2 次，次数为试玩初值；同一怪物与地形掉落不因回溯刷新。危险预告、逻辑顺序与动画同步待完整试玩反馈。**

本次美术接入的图片解码、Canvas 绘制和正式战斗回归检查已通过；DOM 是模拟，完整浏览器布局和连续闯关未验收。素材按用户指出的范围修改，未要求部分及像素不改；不新增重复审核页。用户撤回的上下不对称站姿不再实施。

### 6.3 待办：分阶段整理 HTML 项目代码

**【待执行】暂不开始；等待用户后续指令。** 继续以现有 HTML 版本开发和试玩，先接入美术样板、评估实际效果，再决定是否试验 Godot。优化目标是改善后续美术接入、规则维护和验证；不一次性重写整个项目。

1. **先检查现状并制定顺序**：梳理代码职责、依赖、现有测试和打包方式，识别最影响后续工作的部分；以下顺序为初步建议，按检查结果调整。
2. **资源与画面**：整理资源加载、素材配置和画面表现，为替换角色、怪物、场景及界面素材做准备。
3. **规则与表现**：逐步理清战斗结果和动画播放的边界，使美术调整尽量不改变实际规则。
4. **预测与回溯**：梳理危险预测、怪物实际行动和回溯所依赖的规则与状态，减少结果不一致或状态遗漏。
5. **结构与验证**：按职责逐步拆分代码，保留并按需补充关键行为检查；每阶段验证行为、重新打包并验证双击试玩，保持可玩的版本。

每一步按用户后续指令推进；具体范围和顺序先核对现有实现，不把文件拆分本身当作完成目标。
