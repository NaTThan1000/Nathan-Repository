# Turnbased Shoot 代码审计（2026-11-04）

审计基线：`9887a31`。范围为现役 `src/`、正式适配层、构建工具、配置加载、自动检查及旧工具入口。采用源码调用关系审查、针对性运行复现、现有回归及固定场景 Canvas 对比。没有逐一人工试玩全部房间，也没有测量浏览器帧率。

## 结论与优先级

确有精简空间；同时也存在需要补充验证的状态编码问题和新适配层中的重复界面更新。不能把全部问题归因于早期代码：蓝心适配及快照检查属于本次整理前的近期改动，应一起审查。

### A. 优先处理：公爵关键帧的 Map 恢复发生变形（已复现，尚未修改）

- 位置：`src/state/snapshots.js` 的 `restoreMonsterSnapshot`，以及各恢复路径后续 `new Map(...)` 处理；`src/state/checkpoint-simulation.js` 也有相同后处理。
- 保存时 Map 转换为 `[id, position]` 条目数组。恢复函数又对这个数组使用 `.entries()`，导致条目被加上一层数组索引，随后 `new Map` 得到的键不再是怪物 ID。
- 针对性复现：原 Map 为 `9 → {col:5,row:3}`，经当前保存、恢复和实际后处理后变成 `0 → [9,{col:5,row:3}]`，`has(9)` 为 false。
- 影响：不能保证快照恢复后的公爵推移数据与保存前相同；是否在当前完整流程中被下一次路径计算覆盖、进而掩盖症状，需要补充 Boss 实际回溯用例，不能据局部复现声称必然出现某种游戏故障。
- 测试缺口：当前 `snapshot-codec.test.cjs` 检查了中间嵌套形状，没有断言最终恢复后的键与位置相同；因此现有检查通过并不能排除此问题。这个检查是近期整理时新增的，覆盖不足也属于本轮审计发现。
- 建议：统一明确 Map 与条目数组之间的边界，补上保存→恢复→后处理的完整往返检查，再修正重复编码。为控制本次审计范围，没有顺手改变现役状态恢复语义。

### B. 优先处理：蓝心存在时，HUD 缓存被后加适配绕过（已复现，尚未修改）

- 位置：`scrap-star-game-runtime.js` 的 `scrapUpdateHUD` 包装；基础缓存位于 `src/presentation/scrap-star.js`。
- 基础 HUD 已按状态变化判断是否重建，但包装函数在蓝心大于零时，无论基础缓存是否命中都重新写入整排心形 HTML。render 每次调用该包装。
- 模拟 DOM 复现：蓝心为1、数值不变，调用100次 HUD 更新，发生101次 heart-row 的 innerHTML 写入（首次基础更新加100次包装更新）。这是重复写入次数，不是浏览器性能测试或帧率结论。
- 建议：红心和蓝心使用同一缓存和一次生成流程；补上“状态不变不重建，蓝心增减／半心变化会重建”的检查。本次不改变已审核画面或现役更新行为。

### C. 中优先级：危险预测依赖函数源码和精确文本替换

- 位置：`src/combat/danger-prediction.js` 的 `createDangerSimulationFactory`，`src/combat/prediction-rules.js` 的规则清单。
- 当前通过函数 `.toString()` 和 `new Function` 组建模拟闭包；对子弹的一条条件采用精确字符串替换。未来修改表达式、改名、增加外部依赖时，即使真实规则能运行，也可能破坏模拟或使替换悄然失效。
- 现状：14配置、56阶段和混合回合检查通过，没有据此认定当前预测错误。
- 建议：先检查源码替换目标必须唯一命中，并加强副本状态隔离检查；再按实际维护需要把规则的环境依赖变为显式输入。不要一次性重写全部战斗规则。

### D. 中优先级：保存状态和掉落流程仍存在重复规则

- 怪物保存／恢复已去重，但玩家属性、资源、道具及房间数组同步仍在多处手写。新增状态字段仍可能遗漏，不能把当前模块化当成自动解决回溯完整性。
- `src/items/kill-drops.js` 的预抽掉落与 `src/items/drop-dispatch.js` 的即时掉落存在相似模式处理，但失败分支等细节有区别，不能直接合并。预抽的空数组明确表示“无掉落”，与未预抽不同，必须保留语义。
- 建议：先建立字段与各保存／恢复路径的覆盖表，并对掉落空结果、随机消耗和回溯结果做对照，再抽取公共逻辑。

### E. 低优先级：构建和目录仍可继续收敛

- `tools/inline-resources.cjs` 递归读取全部候选图片，即使正文没有引用也编码后再替换；当前日志里的图片数表示扫描量，不表示最终包确实使用了所有图片。
- 建议：先检查 HTML 是否引用该路径，或生成引用清单，再读取编码。可减少无用构建工作；本次未测量耗时收益。
- `items/drop-dispatch.js` 仍包含子弹与粒子更新；`items/bombs-and-upgrades.js` 同时含炸弹和道具加成；显示适配仍采用覆盖旧函数方式。后续可按维护频率逐块整理，不宜因文件名不理想而删除现役代码。
- 开发依赖版本已有声明但没有锁文件；另一台机器安装及完整浏览器检查尚未验收。
