## MVP 最小闭环

> 填写要点：编号列表，**每一步都必须是可验证的玩家行为/系统结果**，且必须覆盖所有 P0 系统。结尾写"如果这条闭环不成立，不应继续增加什么"。

MVP 不追求【完整形态】，只验证以下闭环：

1. 玩家【行为 1】。
2. 玩家【行为 2】。
3. 系统【结果 1】。
4. 系统【结果 2】。
5. 玩家能进入下一循环，且【状态发生变化】。

如果这条闭环不成立，不应继续增加【范围外内容清单】。

## 风险与校验

> 填写要点：每条风险必须配一个"怎么看出来"的校验方式，禁止只写风险不给校验。

| 风险 | 校验方式 |
|---|---|
| 【系统 1】变成【跑偏形态】，失去【核心价值】 | 玩家是否能【可观察行为】 |
| 【系统 2】变成【独立小游戏】 | 它的输入是否能【回溯到上游选择】 |
| 【资源】压力过重 | 【资源】不足时是【只延迟】还是【惩罚式毁档】 |
| 【结构】过于单调 | MVP 后是否能【自然扩展】，而不是靠堆数值 |
